# 决策记录（ADR 摘要）

每条写清「选了什么 / 为什么 / 代价」。改动前先读这里，别把踩过的坑再踩一遍。

| # | 决策 | 为什么 | 代价 |
|---|---|---|---|
| 1 | **位点与数据同一事务**写目标库 | 崩溃重放天然幂等，不需要 Kafka 事务或分布式协调 | 目标库必须可写；MQ 类 sink 只能退化为至少一次 |
| 2 | **目标库位点是唯一权威**，源端书签只是护栏 | 避免"源端以为读了、目标端没落库"的丢数据 | 目标库不可用时无法推进 |
| 3 | 背压**暂停读**，不暂停 ack | ack 了没落库就是丢；堆 WAL 至少能告警 | 源端磁盘压力，需要 guard 阈值 |
| 4 | **写入单线程有序**，并行只在源端按表拆 | 跨事务乱序会写出因果错误 | 单流上限受源端解码能力限制 |
| 5 | **能力运行时探测**，不按版本号分支 | 8.4 移除 `SHOW MASTER STATUS`、9.x 移除 native 认证、云上还会魔改 | 每个版本都要真机矩阵 |
| 6 | 类型映射**四档**且绝不静默降级 | tinyint(1)、utf8mb4 行宽、timestamptz 都是真坑 | 用户要多点几次确认 |
| 7 | **不拒绝，只提示** | 决定权在用户；工具不该替人做风险判断 | 用户可能选了会出问题的组合，只能把风险写清 |
| 8 | **job_key 指纹**而非名字做身份 | 多实例连同一个库时名字会撞 | 改范围会变成新任务，需要重新初始化 |
| 9 | `gc` **默认只清本实例**的对象 | 防止 A 删掉 B 正在用的书签 | 跨实例清理要 `--force` 并确认 |
| 10 | **不做文档站**，提示即文档 | 用户不看文档；AI 助手读代码和 `--json` 更快 | 提示文案成本高，每条都要写清四段 |
| 11 | 转换**不做聚合/join/脚本** | 复杂逻辑放进视图，边界才守得住 | 用户要自己写视图 |
| 12 | `verify` **三级**，L1 只做可加统计 | PG/MySQL 没有共同可比的行哈希（md5 vs crc32 不同源） | L1 会漏"值互换"，需要抽样兜底 |
| 13 | 状态表结构**只向前迁移**，用数据库锁串行 | 多实例同时启动不能并发改表 | 回滚二进制前必须 `--resync` |
| 14 | 一期**只做 MySQL 与 PG** | 三种组合 × 13 个版本已经够撑满矩阵 | Oracle/达梦/金仓排二期 |
| 15 | **WebUI 是一等控制面，CLI 是运维工具**（2026-11-05 改） | 同步是长期存在的系统，不是一次性脚本；用户要看"现在到哪了"不该靠敲命令 | 多一层 UI 与 API 的工程量，M1 前必须先做 M0.5 |
| 16 | **配置与连接存进内嵌数据库，yaml 只做导入导出** | 密码不该躺在文件/git/聊天记录里；改配置不该编辑文本 | 控制库成为新故障点，需要备份与完整性检查 |
| 17 | **按表暂停 = 跳过该表 + 位点继续前进 + 恢复时整表重搬**（2026-11-11 裁决） | 一张表结构变了不该让几十张无关表一起停；位点只有一个，跳过必须有账可查 | 恢复要重搬该表一遍（大表=一次全量），重搬期间该表与源端不一致；用户自己的表不自动重搬，要人做选择 |
| 18 | **位点只有源端坐标一种，目标端只负责同事务保存与返回** | 目标端没有与源端可比的写位置；同事务提交让回退窗口恒为 0，重放靠 upsert 吸收 | 需要连接器各自实现顺序判定（`Before`）与可重放探测（`Replay`）；MySQL 目标的隐式提交批次多一道落库校验 |
