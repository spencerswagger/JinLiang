# 错误码全集（提示即文档）

每个错误都必须自带四段：**发生了什么 / 为什么 / 你现在能做什么 / 风险**。
代码里是 `internal/core/codes.go`（有测试保证：编号唯一、人话短、每类必有三步以内动作）。

编号首字母决定类别：`E1xxx` 需要你做一件事 · `E2xxx` 自动重试 · `E3xxx` 不可恢复 · `E4xxx` 我们的 bug。

## 需要你处理（user_action）

| 码 | 发生了什么 | 为什么 | 你能做什么 | 风险 |
|---|---|---|---|---|
| E1001 | 源库没开「变更流水」 | 数据库只记了够自己恢复的信息 | `ALTER SYSTEM SET wal_level='logical'` → 重启 → 重跑 `run` | 源库里给外部读取的变更流水体积会增加约 10–20%；重启期间业务连接需要重连 |
| E1002 | 目标端已有同名表 | 默认不覆盖，防误删 | 改 `on_exists: append` / `recreate` / 换 schema | `recreate` 会清空目标表 |
| E1003 | 账号没有读变更的许可 | 复制权限与查询权限是两回事 | `--grant` 让我们建账号授权，或执行提示里的 GRANT | 加权限是持久变更，建议专用账号 |
| E1004 | 连到只读副本 | 副本上读不到变更流水 | 指向主库；或改「定时增量」（只要 SELECT） | 连主库会增加主库压力 |
| E1005 | 已有实例在跑这个同步 | 两个进程写同一份会互相覆盖 | `jinliang status` 确认；等租约过期再试 | 强清租约会短暂双写 |
| E1006 | 视图没有变更流水 | 视图是查询结果，不是存储对象 | 改 `interval` 模式 + 指定水位列；或同步基表 | 定时增量有分钟级延迟 |
| E1007 | 凭据文件权限太宽 | 别的用户能读＝泄露 | `chmod 600 <文件>` 或改用环境变量 | 全产品唯一硬停（安全底线） |
| E1008 | 连不上这个数据库 | 地址、端口、账号口令、证书、防火墙任一不对都会连不上；控制面只做只读探测 | 点「重新测连」看卡在哪一步；确认地址端口能通；口令或证书改过就重填再测 | 无：测连只读版本号与权限，不写数据、不建对象 |
| E1009 | 没有这个接口 | 接口清单见 `docs/CONTROL-PLANE.md` §4；不在这张表里的路径不会假装成功，也不会被网页兜底吞掉 | 对一下 §4 的路径（导出是 `/api/jobs/{id}/export`，`/yaml` 是它的旧别名）；`verify`/`gc` 是 B1 才做 | 无：只影响调用方判断，不改任何数据 |
| E1010 | 进度标记与当前源对不上 | 目标库里存的进度是另一种数据库写的（比如 MySQL 的位点、这次连的却是 PostgreSQL） | 换回当初那个源再跑；确实要换源就删掉目标端同步元数据重跑（会重搬全量） | 重搬全量期间目标端数据会短暂不一致，耗时随数据量增长 |
| E1011 | 一个事务太大，整段缓冲撑不住了 | 按事务整段缓冲（位点才能落在事务边界上），内存≈行数×行宽；超过上限（默认 128 MB / 100 万事件） | 拆小事务（分批 DELETE/INSERT，每批几千行）或先建新表再切换；确实拆不了就调高上限——MySQL 源用 `JINLIANG_TX_MAX_BYTES` / `JINLIANG_TX_MAX_EVENTS`，PostgreSQL 源暂时没有开关 | 调高上限会推高峰值内存（仍是整段缓冲）；改上限等于改提交边界，跑着的任务最好重开一轮 |
| E1012 | 账号没有做这件事的权限 | 数据库拒绝了这条语句（SQLSTATE 42501）：能连上，但没被授予这项操作的权限——源端读表，或目标端建表/写入 | 让 DBA 按提示里的对象授权（源端 GRANT SELECT、目标端 GRANT CREATE/INSERT/UPDATE/DELETE），或换一个有权限的账号重建连接 | 授权是持久变更：建议专用账号并按 schema 限定，别直接给超级用户 |
| E1013 | 缺这个 schema、表或列 | 数据库说这个对象不存在：`3F000` 缺 schema、`42P01` 缺表、`42703` 缺列（源端表结构变过，水位列改名/删掉也是这个） | **先看 SQLSTATE**：`3F000` → 建 schema 或换已有 schema；`42P01` → 别建 schema，确认表名大小写/前缀或回任务页重选表范围；`42703` → 回任务页重跑预检，确认水位列还在；改完直接重跑（位点不动，不必重搬） | 换 schema 等于换一套目标表：旧 schema 里的数据不会自动搬过去 |

## 自动重试（retryable，5s/20s/60s，<=3 次）

| 码 | 发生了什么 | 你能做什么 | 风险 |
|---|---|---|---|
| E2001 | 目标库断开连接 | 一般会自动恢复；持续出现查连接数上限/空闲超时 | 重试期间源端变更会积压，注意「同步进度落后」告警 |
| E2002 | 源库响应超时 | 降低 `snapshot.conns` / `max_read_qps` | 初始化变慢 |
| E2003 | 目标库等锁超时 | 检查目标端长事务 | 重试持续占用连接 |

## 不可恢复（fatal）

| 码 | 发生了什么 | 你能做什么 | 风险 |
|---|---|---|---|
| E3001 | 同步进度与源库变更流水接不上 | `run --resync` 重新初始化；把源库保留时间调长 | 重搬全量，期间目标端可能短暂不一致 |
| E3002 | 状态表版本比二进制新 | 换回新版本二进制，或 `--resync` 重建 | 降级不回退状态表结构 |

## 我们的 bug（bug）

| 码 | 发生了什么 | 你能做什么 | 风险 |
|---|---|---|---|
| E4001 | 遇到字典外的类型，已按文本兜底 | 手动指定该列类型；把类型名反馈我们 | 文本兜底丢类型语义 |
| E4002 | 解码器内部状态不一致 | 保留日志提 issue；临时删任务重初始化 | 重搬全量耗时 |

## 文案纪律

- `Message` <=40 个汉字，且**不出现** WAL / LSN / GTID / slot / publication / LogMiner。
- `Next` 一到三条，必须带**可直接执行的命令或具体位置**，不写“请检查配置”这类空话。
- 任何一条都不许以“拒绝”收尾：能跑就提示风险，跑不了就说清缺什么。
