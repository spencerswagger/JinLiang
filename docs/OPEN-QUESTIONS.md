# 未决问题（需要拍板或实测后才能定）

| # | 问题 | 影响 | 倾向 |
|---|---|---|---|
| 1 | MySQL 无主键表：允许同步但 insert-only？还是超过 N 行直接拒绝？ | 决定预检严格度 | 允许并标「不可续跑、不可 upsert」，超 50 万行建议加主键 |
| 2 | `_ds_*` 落在目标库哪个 schema | 多租户/权限 | 默认与目标表同 schema，可配 |
| 3 | 是否支持视图作为源 | 只快照、无增量 | 支持快照，增量明确不支持 |
| 4 | 大事务 spill 目录默认位置与磁盘上限 | 稳定性 | 与状态目录同盘，上限可配，默认 5 GB |
| 5 | `interval` 模式的水位存哪 | 需要 `_ds_meta.watermark` 字段 | 加一列 `watermark text`（DDL 待补） |
| 6 | `newest` 冲突策略在 PG `track_commit_timestamp=off` 时的口径 | 准确性 | 只用列上的时间戳，拿不到就退化为 manual |
| 7 | 是否暴露 REST/gRPC 控制面 | 部署复杂度 | 不做，CLI + 指标端点足够 |
| 8 | 死信 `raw_row` 是否默认存 | 敏感数据 | 默认存，可配 `none` 只存哈希 |
| 9 | 二进制名与仓库名之外，是否要独立文档站 | 发布 | 先 README + docs/，站点后置 |
| 10 | MariaDB 何时接 | binlog 同族，成本中等 | 二期，先看 MySQL 稳定性 |
