## 3. 指纹为什么 9.x 换了算式（不是放水）

- 口径①（矩阵主口径）：两端各自按主键逐行 `md5(concat_ws('|', id, payload))` 拼接后再取摘要。
- **MySQL 9.x 起内置 `MD5()` 已被移除**：直接跑原算式会得到
  `ERROR 1305 (42000) at line 1: FUNCTION jinliang_target.MD5 does not exist`（原文，最小复现见 §4.3）。
  这是**服务器端函数没了**，不是引擎问题（引擎的哈希在 Go 侧算，`internal/` 里没有 SQL `MD5(`）。
- 处理：`acceptance_matrix.sh` 改成**能力探测**（`SELECT MD5('x')` 有就用 md5、没有就 SHA2(...,256)，
  不按版本号分支），两端同算式：MySQL `SHA2(CONCAT_WS('|',id,payload),256)` vs
  PG `encode(sha256(convert_to(concat_ws('|',id,payload),'UTF8')),'hex')`。指纹值变成 64 位十六进制，
  判据（行数 + 两端相等）没变松。**口径已在主干脚本内**（#110 已把这段能力探测吸收进 `scripts/acceptance_matrix.sh`，main `f1e12c5` 上无 patch 复跑 9.7.4 三组合 20000=20000 全过），本目录不再附带补丁文件。
- 口径②（第二口径，`scripts/matrix3_export_md5.sh`）**四档都是纯 md5、没有函数依赖**，四档全 `equal=yes`，
  所以 9.x 那档的「一致」有独立于 SHA2 的证据。

### 4.1 取二进制（含 sha256，便于核对是不是同一份）

```bash
export SSL_CERT_FILE=/.toolchain/certs/ca-certificates.crt   # 沙盒缺 /etc/ssl
# 5.7：官方通用包（阿里云镜像，13 MB/s）

# sha256 f29fec8a0d7a774c874d6ab0a049ee2cfd9cb0e1a59de818576e039b19dc3aa4
tar xzf mysql-5.7.38-linux-glibc2.12-x86_64.tar.gz -C /.toolchain/

# 8.4 / 9.x：Oracle APT 的 Debian 13 deb（repo.mysql.com，国内镜像 mirror.nju.edu.cn/mysql/apt 同源、约 10 MB/s）
#   组件名：mysql-8.4-lts / mysql-9.7-lts；包：mysql-common、mysql-community-client-core、
#   mysql-community-client、mysql-community-client-plugins、mysql-community-server-core
#   sha256（server-core）8.4.13 = edc13c0973ebf739dfdbe11076275bd39ec06a0eee19c3655cfecdb93c4f8ba8
#   sha256（server-core）9.7.4  = 327eab739d1ea7e38aa9e674412f51a73ea11dbb2988ee3a847f2c41fea360c6
for f in mysql-common_8.4.13-1debian13_amd64.deb mysql-community-client-core_8.4.13-1debian13_amd64.deb \
```

### 4.3 9.x 的 MD5() 缺失（原文 + 最小复现）

```
$ mysql --protocol=TCP -h 127.0.0.1 -P 53347 -ujinliang -p"$PASS" -e \
    "SELECT CONCAT(COUNT(*),':',MD5(GROUP_CONCAT(h ORDER BY id SEPARATOR '')))
       FROM (SELECT id, MD5(CONCAT_WS('|', id, payload)) h FROM acc_pm) x" jinliang_target
ERROR 1305 (42000) at line 1: FUNCTION jinliang_target.MD5 does not exist
```
`SELECT SHA2('a',256)` 在同一实例可用。**口径已在主干脚本内**（`scripts/acceptance_matrix.sh` 已含
能力探测，无需打补丁；#110 合入后 main 上直接可跑 9.x）。

### 4.4 各档「起得来」的三处环境适配（都是跑测试栈的活，不是引擎改动）

1. **5.7 无 `--mysqlx`**：`local_stack.sh` 的启动行带 `--mysqlx=OFF`，5.7 不认这个变量会直接退出。
   该档用同一份脚本删掉这一个参数（`--stop-when-idle` 等场景参数一律没动）。
2. **5.7 自带客户端缺 `libncurses.so.5`**（Debian 13 只有 `.so.6`）：`mysql`/`mysqladmin` 起不来，
   所以 `MYBASE=/.toolchain/mybase-5.7.38` 是个 shim：`bin/mysqld` 指 5.7 的 mysqld，
   `bin/mysql`、`bin/mysqladmin` 指 8.0.28 的客户端（8.0 客户端连 5.7 服务器正常）。
   **被测引擎连的仍是 5.7 服务器**（go-sql-driver，日志与 `doctor.log` 都打印 `5.7.38-log`）。
3. **8.4 / 9.x 的 Debian 包默认 `secure-file-priv=/var/lib/mysql-files`**：目录不存在时
   mysqld 启动即 `[ERROR] [MY-010095] Failed to access directory for --secure-file-priv` 并 abort。
   建目录（`chmod 777`）即可，不改任何服务器参数。
   （沙盒另有一坑：`/dev/null` 是普通文件且 0644，PG 以 postgres 身份 initdb 会
   `cannot create /dev/null: Permission denied`，`chmod 666 /dev/null` 解决。）

## 5. 实例口径（`instance.txt`，每档一份）

| 档 | version | log_bin / format / row_image | binlog_row_metadata | gtid_mode | 认证默认 |
|---|---|---|---|---|---|
| 5.7.38 | `5.7.38-log` | ON / ROW / FULL | **无此变量**（5.7 没有列名元数据，走 catalog 按序号补） | `OFF` | `mysql_native_password` |
| 8.0.28 | `8.0.28` | ON / ROW / FULL | `MINIMAL`（binlog 里没列名，靠 catalog） | `OFF` | `caching_sha2_password` |
| 8.4.13 | `8.4.13` | ON / ROW / FULL | `MINIMAL` | `OFF` | `authentication_policy=*,,`（无 native 默认） |
| 9.7.4 | `9.7.4` | ON / ROW / FULL | `MINIMAL` | **`ON`（9.x 默认开）** | `authentication_policy=*,,` |

两点值得记：
- **9.x 默认 `gtid_mode=ON`**，所以 9.7 这档的 MySQL 源是**带 GTID 的 binlog**，照样读到 `file=mysql-bin.000003;pos=…` 并追平；
- 8.4/9.x 默认认证插件是 `caching_sha2_password`（5.7/8.0 我建的是 native）——驱动侧
  `go-sql-driver/mysql v1.10.1` 直连通过，没有额外 DSN 参数。

## 6. 覆盖边界（明写，不冒充）

1. **GTID 维度不算覆盖**：只有 9.7 是默认 `gtid_mode=ON`；5.7/8.0/8.4 的 `gtid_mode=OFF`
   （A 的 `local_stack.sh` 没开 GTID，我没改场景）。要「四档 GTID 全覆盖」得另开一档
   （`--gtid-mode=ON --enforce-gtid-consistency=ON` 重跑 5.7/8.0/8.4），说一声我跑。
2. **没有容器/镜像档**：沙盒无 docker（testcontainers 矩阵在 GitHub Actions），所以「实例来源」是官方
   二进制/deb，不是容器 tag；要容器口径只能去 CI 加 matrix。
3. 每档是**本地单机单实例**（源/目标两个 mysqld 同版本、不同端口），不复现主从拓扑。
4. 只测了 `ROWS=20000` 一档数据量（与 A 一致）；10 万级行数没在四档重跑。

## 7. 一条与版本无关的注意项（四档一致，不是版本差异）

四档的 `doctor.log` 都报 `[注意] target 运行时表不完整 缺：_jl_version`，而
`internal/runtime/tables.go` 只有常量定义、`internal/doctor/doctor.go` 把它列进 required，
**代码里没有创建这张表的路径**。四档表现完全相同，所以不是版本问题；建议另立小单给 Core
（要么 doctor 别要求它，要么 EnsureSchema 建它）。doctor 的退出码四档都是 `exit=0 结论 正常`。
